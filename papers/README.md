## 如何选定投稿论文

建议按以下顺序阅读三篇 docx 文件，然后择一投稿：

1. 打开 `论文A-全景平台.docx`，检查是否符合"讲清整个平台"的需求；
2. 打开 `论文B-多租户双模.docx`，检查是否符合"深挖多租户技术"的需求；
3. 打开 `论文C-AI可插拔.docx`，检查是否符合"AI 应用与治理"的需求；
4. 挑选最匹配的一篇作为**投稿论文**，另外两篇可作为备用或后续研究成果；
5. 也可以对某一篇进行"重写+扩容"（比如把论文 B 扩为 8000 字投中文核心期刊）。

## 如何填写占位符 `[待填]`

团队成员的姓名已在正文中全部填好，剩下的占位符只需要用户补充少量事实信息即可。可通过以下命令一次性列出全部占位符：

```bash
cd /root/projects/campus/papers
grep -n "\[待填\]" *.md
```

**结题报告需要填**：
- 项目级别（国家级/自治区级/校级）与项目编号
- 石昌妮的学号与专业
- 石昌妮加入团队的时间
- 实际经费明细（4 个开支科目分别使用了多少）
- 平台上线域名
- GitHub 开源仓库地址
- 软件著作权证书号（如已申请）
- 最终投稿论文的题目、期刊、卷号、期号、页码、录用日期
- 附录 1 五张平台截图
- 附录 2 结题成果数据统计表的数值列

**三篇论文都需要填**（少量）：
- 基金项目行中的"国家级/自治区级/校级"字样
- 基金项目行中的项目编号
- 收稿日期（论文实际投稿时期刊会盖新日期，无需现在改）

## 如何重新生成架构图

如果需要修改架构图，编辑 `assets/*.mmd` 源文件后：

```bash
cd /root/projects/campus/papers/assets

# 需要有系统 chrome 且已装中文字体
cat > /tmp/puppeteer-config.json << 'EOF'
{ "executablePath": "/opt/google/chrome/chrome", "args": ["--no-sandbox"] }
EOF

for fig in fig-总体架构 fig-多租户双模 fig-AI集成架构; do
  mmdc -p /tmp/puppeteer-config.json -i "${fig}.mmd" -o "${fig}.png" -b white -w 1600
done
```

## 如何重新生成 Word 文件

修改 md 后：

```bash
cd /root/projects/campus/papers
for name in "论文A-全景平台" "论文B-多租户双模" "论文C-AI可插拔" "结题报告"; do
  pandoc "${name}.md" -o "${name}.docx" --standalone
done
```

> 如需更细致的 Word 样式（宋体正文、黑体标题、单倍行距等），准备一个 `template.docx`
> 作为样式源，然后加参数 `--reference-doc=template.docx` 即可。

## 参考文献注意事项

参考文献池位于 `refs/参考文献池.md`，共 25 条候选，按 8 个主题分组：政策文件、多租户 SaaS、Docker/微服务、RAG/大模型、Web 安全、高校信息化、技术标准、AI 服务治理。

**投稿前请务必**：

1. 逐条到中国知网、万方、维普验证真实性；
2. 对于文献池中标注"可替换"的条目，请替换为你能实际检索到的相似主题真实文献；
3. 参考文献列表按被引顺序排列（GB/T 7714 顺序编码制），一处引用一个编号；
4. 论文正文里的 `[1] [2]` 编号要与参考文献列表严格对应，不要缺失或错位。
